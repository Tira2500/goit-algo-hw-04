# Порівняльний аналіз алгоритмів сортування

## Алгоритми

- **Сортування злиттям** (Merge Sort) — рекурсивно ділить масив навпіл, сортує частини і зливає їх. Складність: O(n log n).
- **Сортування вставками** (Insertion Sort) — по черзі вставляє кожен елемент на правильну позицію. Складність: O(n²).
- **Timsort** — вбудований алгоритм Python (`sorted`, `list.sort()`). Гібрид сортування злиттям і вставками. Складність: O(n log n).

## Аналіз результатів

### Сортування вставками
Найповільніший алгоритм на великих масивах. На масиві з 10 000 елементів витрачає **2.4 секунди** — у 97 разів повільніше за злиття і у 1700 разів повільніше за Timsort. Це підтверджує теоретичну складність O(n²).
Підходить лише для малих масивів (до 100 елементів) або майже
відсортованих даних.

### Сортування злиттям
Значно краще за вставками на великих масивах завдяки складності O(n log n).
На 10 000 елементів — **0.025 секунди**. Однак програє Timsort через
накладні витрати на рекурсію та створення нових масивів при злитті.

### Timsort
Найшвидший алгоритм у всіх тестах. На масиві з 10 000 елементів —
**0.001 секунди** — у 17 разів швидший за злиття. Перевага Timsort
полягає в тому, що він:
- реалізований на рівні C (а не Python)
- використовує сортування вставками для малих блоків (де воно ефективне)
- використовує злиття для великих блоків
- враховує вже відсортовані підпослідовності в реальних даних

---

## Висновки

1. **Timsort є безумовним переможцем** у всіх сценаріях тестування.
   Поєднання двох алгоритмів дозволяє використовувати переваги кожного:
   вставками — для малих блоків, злиттям — для великих.

2. **Сортування вставками** має сенс лише для малих або майже
   відсортованих масивів. На великих даних його використання недопустиме.

3. **Сортування злиттям** — надійний алгоритм з гарантованим O(n log n), але поступається Timsort через накладні витрати реалізації на Python.

4. **Практичний висновок**: у реальних проєктах завжди слід використовувати вбудовані функції `sorted()` або `list.sort()`. Вони реалізовані на C, оптимізовані роками і враховують особливості реальних даних. Писати власний алгоритм сортування виправдано лише в навчальних цілях або вузькоспеціалізованих задачах.
